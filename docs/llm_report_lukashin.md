## Hugging Face NLP Course

Курс охватывает практическую работу с трансформерными моделями через библиотеку `transformers`. Структура: от базовых понятий (токены, эмбеддинги) до тонкой настройки моделей на собственных данных.

**Что изучил:**

Архитектура Transformer строится на механизме self-attention: каждый токен входной последовательности взаимодействует со всеми остальными одновременно. Это принципиально отличает трансформеры от рекуррентных сетей, где информация передаётся последовательно.

Разница между типами моделей:
- Энкодерные (BERT, RoBERTa) — двунаправленный контекст, подходят для классификации и понимания текста
- Декодерные (GPT, LLaMA) — однонаправленная генерация, подходят для создания текста
- Encoder-decoder (T5, BART) — для задач seq2seq: перевод, суммаризация

Hugging Face Hub позволяет находить готовые модели, включая русскоязычные, и оценивать их по метрикам до загрузки. Это снижает порог входа: не нужно обучать с нуля, достаточно найти подходящий чекпоинт.

## Введение в LLM (Stepik)

Курс посвящён теоретическим основам и практическому применению больших языковых моделей. Акцент — на понимании ограничений и корректной работе с моделями.

**Что изучил:**

Авторегрессионная генерация: модель предсказывает следующий токен на основе предыдущих. Итоговый текст — результат многократного повторения этого предсказания. Отсюда следует, что формулировка запроса напрямую влияет на распределение вероятностей для первых токенов ответа.

Параметры, которые управляют «поведением» генерации:

| Параметр | Низкое значение | Высокое значение |
|----------|----------------|-----------------|
| `temperature` | Точные, предсказуемые ответы | Разнообразные, иногда неожиданные |
| `top_p` | Выбор из узкого набора вероятных токенов | Шире пространство выбора |
| `top_k` | Только k наиболее вероятных вариантов | Больше вариантов при сэмплинге |

Галлюцинации возникают не из-за «незнания» — модель не имеет понятия «я не знаю». Она всегда генерирует наиболее вероятный ответ в данном контексте, даже если фактической основы нет. Минимизация: чёткие инструкции, ограничение области ответа, верификация вывода.

Раздел про российские LLM (GigaChat, YandexGPT, ruGPT) оказался особенно применимым: GigaChat обучен на русскоязычном корпусе, что даёт преимущество при генерации текстов с культурным контекстом — названия блюд, единицы измерения, привычные формулировки.

## Применение в рамках практики

В ходе работы над проектом занимался двумя направлениями.

**Анализ возможностей GigaChat.** Провёл сравнение качества ответов при разных значениях `temperature` для задачи генерации рационов. Вывод: значение 0.8–0.9 даёт оптимальный баланс между структурированностью и разнообразием блюд. При 1.2+ начинаются отклонения от заданного формата.

**Разработка промптов для функции «Блюда из холодильника».** Итерировал формулировки, фиксируя изменения в результатах:

```
Версия 1 — без структуры:
"Предложи блюда из этих продуктов: курица, яйца, помидоры"

Результат: неструктурированный текст, разная длина ответа, иногда markdown-разметка

Версия 2 — role prompting + явный формат:
"Ты повар-диетолог. Предложи ровно 3 диетических блюда.
Для каждого: название, состав с граммовкой, калорийность, рецепт.
Нумеруй: 1️⃣, 2️⃣, 3️⃣. Не используй markdown."

Результат: стабильный формат, удобный для отображения в Telegram
```

Ключевой вывод: явная роль + ограничение формата + количество пунктов — три компонента, которые делают вывод LLM предсказуемым. Убрав любой из них, качество падает.
